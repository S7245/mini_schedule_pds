# Batch 01 测试场景 — 公开注册流程

执行方式：browser-automation skill 或 senior-qa skill 生成 Playwright 脚本

前置条件：
- api-brand 在 localhost:8081 运行
- brand 前端在 localhost:3002 运行
- 测试手机号未在 brand_users 表中注册

---

## Happy Path

| # | 步骤 | 预期结果 |
|---|---|---|
| H1 | 访问 `http://localhost:3002/signup` | 显示注册表单，步骤条高亮"注册信息" |
| H2 | 输入手机号 `13800138099`，点"发送验证码" | 按钮进入 60s 倒计时 |
| H3 | 输入验证码 `123456`，密码 `test1234`，品牌名称 `测试品牌`，联系人 `张三` | 无报错 |
| H4 | 点"下一步：选择套餐" | 调用 pre-validate 成功，跳转 `/signup/plan`，步骤条高亮"选择套餐" |
| H5 | 页面加载出套餐列表 | 至少显示 1 个套餐卡片 |
| H6 | 点击任意套餐卡片 | 卡片高亮，底部显示已选摘要 |
| H7 | 点"立即支付" | 跳转 `/signup/payment/[order_id]`，步骤条高亮"扫码支付" |
| H8 | 支付页显示二维码区域和倒计时 | 二维码容器可见，倒计时格式为 `mm:ss` |

---

## Edge Cases — 注册信息页

| # | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| E1 | 密码少于 8 位 | 输入密码 `abc123`，点"下一步" | 显示"密码至少 8 位" |
| E2 | 密码无数字 | 输入密码 `abcdefgh`，点"下一步" | 显示"密码必须包含数字" |
| E3 | 密码无字母 | 输入密码 `12345678`，点"下一步" | 显示"密码必须包含字母" |
| E4 | 手机号格式错误 | 输入 `12345`，点"下一步" | 显示"请输入正确的手机号格式" |
| E5 | 手机号已注册 | 使用已注册手机号，点"下一步" | pre-validate 返回"该手机号已注册" |
| E6 | 验证码错误 | 输入验证码 `000000`，点"下一步" | pre-validate 返回"短信验证码错误" |
| E7 | 品牌名称为空 | 不填品牌名称，点"下一步" | 显示"品牌名称不能为空" |
| E8 | 联系人为空 | 不填联系人，点"下一步" | 显示"联系人姓名不能为空" |

---

## Edge Cases — 选择套餐页

| # | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| E9 | 未选套餐直接点"立即支付" | 不选套餐，点按钮 | 按钮处于 disabled 状态，无法点击 |
| E10 | 直接访问 /signup/plan（无 sessionStorage） | 清空 sessionStorage 后访问 | 自动跳转回 `/signup` |

---

## Edge Cases — 支付页

| # | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| E11 | 支付配置缺失时的 error 状态 | 访问 `/signup/payment/999` | 显示"获取二维码失败"和重试按钮 |
| E12 | 点"重新获取二维码" | E11 状态下点击重试按钮 | 重新调用 API |
